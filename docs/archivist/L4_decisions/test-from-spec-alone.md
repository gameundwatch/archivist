# テストコードは spec だけを読んで書ける

test は spec の実現であり、design を読まずに書ける。design に依存する検証は
test ではない。

覆しにくい決定。

test が design に依存すると、振る舞いが変わっていないのに設計を書き直しただけで
壊れる。そのテストは約束ではなく設計を検証している。テストの書き手と実装の
書き手が別であるとき、この依存は成立しない。

この決定は spec の書き方に要求を課す。V は、それだけを読んでテストコードが
書ける詳しさで書く。書けないなら、判定の内容が足りていない。パス名や外に公開された名前は
外から観測できる語彙なので、spec に書いてよい。内部の作りを前提とする記述だけが
design に属する。

実装内容の細部に口を出すものは test ではなく lint にあたる。lint は design の
側に属し、spec は関知しない。
