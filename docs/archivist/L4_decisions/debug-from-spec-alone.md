# debug は spec だけを読んで書ける

debug は spec の実現であり、design を読まずに書ける。design に依存する検証は
debug ではない。

覆しにくい決定。

debug は成果物を実環境で実際に動かし、その内容 (What) が約束通りかを判定する。
E2E も受け入れテストも、走らせるのが人か機械かを問わず debug に属する。

debug が design に依存すると、振る舞いが変わっていないのに設計を書き直しただけで
壊れる。その検証は約束ではなく設計を検証している。検証の書き手と実装の書き手が
別であるとき、この依存は成立しない。

この決定は spec の書き方に要求を課す。V は、それだけを読んで debug が書ける
詳しさで書く。書けないなら、判定の内容が足りていない。パス名や外に公開された
名前は外から観測できる語彙なので、spec に書いてよい。内部の作りを前提とする
記述だけが design に属する。
