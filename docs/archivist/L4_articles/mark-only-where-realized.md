# 印が付くのは実現先を持つ層だけ

`_` は feature / spec / design に付く。structure と terms には付かない。

`_` は「実現先がまだ実在しない」を示す。実現先を持たない文書は、実現先の有無で
状態が変わらない。articles を対象外にしたのと同じ理由が、structure と terms にも
当てはまる。どちらも条項の像であり、条項が決まった時点で事実になる。

外れる条件は層ごとに違う。いずれも実現先が在るかどうかで、実現先を動かして得られる
生成物は見ない。

- design — Parts の `target_file` 列が挙げるファイルが在るとき
- spec — 全ての V が手段を持ち、ファイルを宣言したものはそれが在るとき
- feature — 参照する spec と design が両方事実になったとき

feature だけは自分の実現先を持たない。破線を持つのは spec と design の二つで、
feature は参照の向きに沿って下から状態を受け取る。
