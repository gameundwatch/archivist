# 層は飛ばさない。decisions だけが例外

参照は直下の層にだけ張る。ただし decisions はどの層からも直接指せる。

層を飛ばせると、各層の文書が自分の高さで完結しなくなる。feature が
実装ファイルを直接名指しすれば、spec も design も読まずに実装できてしまい、
中間の層が空洞になる。

decisions を例外にするのは、どの層のどの記述にも理由があり得るため。
非機能要件は design に直接効き、「しない」という決断は spec のスコープに
直接効く。理由は層の距離を持たない。

sources には同じ例外を認めない。指すには文書側がファイルの中身を
知っている必要があり、それは design の職務にあたる。
