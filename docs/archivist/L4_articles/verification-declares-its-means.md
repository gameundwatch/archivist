# 検証は自分の手段を宣言する

各 VERIFY は、それが何によって実行されるかを `手段:` の行で持つ。
テストコードならそのファイルパス、人が通すなら `checklist` と書く。

検証の実現形は二つある。自動で走るテストコードと、人が上から通すチェックリスト。
ブラウザ上での確認や、スキルのように自動化できない対象では後者しか取れない。

宣言が無いと、spec が事実になったかを測れない。テストコードなら「そのファイルが
在るか」、チェックリストなら「V がそれだけで実行できる詳しさか」で測り方が違う。
どちらの形かは spec の外から推測できない。

チェックリストの成果物は spec の `## Verify` 節そのものになる。宣言があるから
それを成果物として認めてよく、宣言が無いまま同じ扱いをすると、書いた瞬間に
事実になるのと区別が付かない。

検証が通ったかどうかは archivist の担保する範囲にない。手段が用意されていれば足りる。
