# 対応表は availability から L2 への向きだけを要求する

feature の Coverage 表は、各 availability が spec と design を持つことだけを求める。
どの行からも指されない `R` や `T` は不備にしない。

逆向きも求めると、L2 の全てが L1 で説明されることを要求したことになる。条項は
どの層にも直接効くので、availability を持たないまま design にだけ効く条項がある。
非機能要件がそれにあたる。逆向きの判定を残すと、その条項を通すために利用者が
名指ししないものを availability として L1 に置くほかなくなり、機能の分解が濁る。

触れていない層の不在は違反ではない。条項から design にだけ届いた要求が L1 に
現れないことは、同じ理由で不備ではない。

「作ったが約束していない」は、availability の design 列の空欄で捕まえられる。
指されない `T` の正当性は、その design が持つ条項が担う。
