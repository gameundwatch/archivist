# スキルは文書の要素ごとに割る

archivist はオーケストレーターとし、term / structure / spec / design /
feature / check を独立したスキルとする。

テンプレート5枚とスキル5本が一対一に対応する。どのスキルがどの書式を
持つかに迷いが生じない。書式の知識がスキル側に、伝播の判断が
オーケストレーター側に分かれる。

層ごとに割らないのは、還元がどこで止まるかを条項の中身が決めるため。
呼ぶ側が層を指定すると、伝播の判断を人が負うことになる。

起動順は書く向きに従い term → structure → spec → design → feature。
参照の向きはその逆になる。

check だけ出力が違う。articles と docs/archivist/ 全体を読み、
文書を起こさずに判定を返す。
